怎麼運作

從 Claude Code 發生一件事，到牧場上的寶可夢有反應，中間只經過本機。

  1. 1

    Claude Code 的 hooks

    使用者層級 ~/.claude/settings.json 掛了 hooks：送出提示、用工具前後、要權限、整理記憶、做完一輪、session 結束都會觸發。

  2. 2

    pet-hook.sh

    repo 的 hooks/ 資料夾裡的小腳本，把事件 POST 到 127.0.0.1:47821。這個 port 一次只能給一個程式用。

  3. 3

    Electron 主行程

    只聽本機、拒絕帶 Origin 的請求，只取安全的簡短說明。每個 session_id 認養一隻，存在 ranch.json，重開 App 還在。

  4. 4

    three.js 牧場

    畫面這邊決定寵物怎麼動、泡泡怎麼畫、播什麼音效。模型是 GLB（glTF 2.0），骨骼動畫內嵌。

Hook 事件 → 寵物的狀態
事件寵物
SessionStart上線（第一次看到這個 session 就認養一隻）
UserPromptSubmit、PostToolUse白色泡泡「思考中…」
PreToolUse白色泡泡「動詞：說明」，例如「跑指令：執行型別檢查」；問你問題、計畫等你確認是黃色
PermissionRequest黃色「需要你確認」＋叮咚聲，停下來面向你
PostToolUseFailure紅色「○○失敗了」＋低音、播攻擊動作（按 Esc 中斷不算）
PreCompact淡紫「整理記憶中…」
Stop綠色「做完了！」＋上揚三音、播開心動作
SessionEnd變成「下線」，寵物留著，之後會去睡覺

子代理不另外養寵物：子代理的事件只算「這個 session 還有動靜」（不會睡著），子代理要權限時一樣變黃。

牧場的日常

認養

新 session 第一次有 hook，就從牧場上還沒有的品種裡隨機挑一隻（151 隻都有人養了才重複）。對應關係記在 ranch.json。

自由活動

待機幾秒 → 挑個地方走過去，偶爾用跑的、偶爾原地開心一下。會繞開池塘、樹，跟別隻保持距離。agent 在忙時照樣逛，只是頭上多一朵泡泡。

睡覺

5 分鐘沒有這個 session 的 hook，有睡覺動作的寶可夢（151 隻裡 114 隻）就躺下、飄 Zzz；下一個 hook 一來就醒，先伸個懶腰再開始逛。

打架

兩隻醒著的正面撞上時有 35% 機率開打：面對面各連續攻擊 2～3 次（每場隨機），隨機一隻贏（開心），輸的往牧場另一頭逃跑。同一對 30 秒內只擲一次骰子，整座牧場兩場架至少隔 10 秒。

會飛的

每個動作的離地高度在開模型時各量一次，最多浮 0.3 個身高，不會飛出牧場；泡泡也跟著抬高。

滑鼠

游標在草地上才接滑鼠，其他地方點得到後面的視窗。點寵物＝摸一下（開心＋名牌），按住草地拖曳＝搬牧場。

兩種模式

從 Dock 圖示按右鍵切換，記在 settings.json。

置頂小牧場（預設）

  • 透明、置頂、無邊框的小視窗，在桌面右下角
  • 可以點寵物、拖曳搬牧場
  • 拖到哪個螢幕就換成適合那個螢幕的大小，位置記在 window.json

桌布模式

  • 鋪滿選定的螢幕，在所有視窗與桌面圖示底下，透明背景看得到原本的桌布
  • 收不到滑鼠（不能點寵物、拖曳）
  • 「桌布放在哪個螢幕」可以選，那個螢幕拔掉就回到主螢幕

Dock 選單

寵物不會因為 session 結束而消失。要拿掉一隻，從 Dock 圖示右鍵找到牠，選「放生…」確認就好（桌布模式下確認框會出現在主螢幕）。想一次清空，選「全部放生…」。

同一個選單可以切換模式、選桌布的螢幕、重新掃描模型資料夾，或直接打開模型資料夾。

模型與授權

151 隻模型來自 06wj/pokemon（固定 commit），每個 GLB 下載後先用 scripts/verify-model.mjs 檢查： glTF 2.0、全部內嵌、沒有外部網址、沒有不認得的擴充，才搬進模型資料夾。

🔴 原專案程式是 MIT，但角色模型的權利屬於原權利方，原作者明說不授予使用權。模型放在專案裡的 models/（.gitignore 排除），只給本機自用，不進 git、不分享、不打包進 App。 這個展示網站也一樣：開發伺服器直接讀那個資料夾，沒有複製任何模型或頭像。
